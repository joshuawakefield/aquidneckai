### Exact proposed admission contract

`AQAI_PUBLIC_READER_ENABLED` absent or the exact string `false` retains staging-private reader/static access. Only exact `true` requests public-reader mode. Empty, padded, mixed-case or other values stop startup before listening, without echoing the value. The existing minimum-length staging credential is required in both modes. There is no new account, auth provider, token, cookie, role, endpoint for configuration, or production fixture mode. This is a process-start setting; runtime query parameters/headers cannot switch it.

Raw request paths are checked **before** URL normalization. Percent-encoded paths (including ordinary encoded aliases), dot segments, double slash, backslash, absolute-form targets, semicolons, control characters, fragments and unsupported path characters are rejected with no-store 404. This deliberately accepts only canonical ASCII application/build paths; it does not redirect or decode aliases. The query portion does not select routes/files. Invalid targets may be rejected earlier by Node's HTTP parser. GET/HEAD are the only reader/feed/static methods; other methods are 405, except the already-protected editorial POST. HEAD returns no body.

A missing/malformed manifest, invalid static dependency reference/type/path, dynamic entry in the static graph, missing required file or symlink alias prevents opt-in startup. Disabled mode does not need a manifest. At request time removed admitted files return no-store 404, without fallback; symlinks inside or outside the build are rejected. Read/backend failures return generic no-store 503 without exception details. API boundaries cannot be crossed by path decoding. Builds are trusted release artifacts: require a reviewed, immutable/read-only tree and atomic replacement, not a concurrently mutable dist directory. This is not protection against an attacker who can modify the running application or build manifest.

All responses retain noindex/nofollow, nosniff and framing protections and add `Vary: Authorization`. Public reader HTML/assets use no-store even when a credential is supplied. Private authenticated assets retain existing private immutable caching; auth/error/private API responses remain no-store. The existing public feed alone retains `public, max-age=30, s-maxage=60`; its 60-second server read cache and downstream caches mean withdrawals are not instant. No new cookies or permissive CORS headers. No-store does not erase copies already downloaded, and disabling this flag does not withdraw the pre-existing anonymous feed/health surfaces.
