## Contract v1

[Normalizer and display labels](../../scripts/offline/news-provenance.mjs), [fictional examples](../../scripts/offline/news-provenance-fixtures.mjs), [regressions](../../scripts/test-news-provenance.mjs). These are offline development aids, not a database schema, API version, source enrollment or approval mechanism. No new dependencies. Only the offline test runner imports the tests; application code does not import the contract.

The input is one reviewed story record or an explicitly incomplete lead. Missing/invalid facts become `null` or `unknown`, never a guessed value. A claim is `{value, evidenceUrl}`; both are required. A source date additionally yields `{value, precision, reason, evidenceUrl}`. A pointer means the assertion can be traced to that supplied evidence; the module does not fetch it or prove the assertion true. Input prose/URLs must already be suitable for public use.

| Field | Meaning and minimum evidence | Reader behavior / unknown handling |
| --- | --- | --- |
| `sourceUrl` | Absolute HTTP(S) URL of the specific story when identified; a page URL only with page scope. | Link this inspected asset, never silently replace it with a publisher homepage or inferred original. Invalid/credential-bearing links become unknown. |
| `provenanceScope` | `story`, `syndicated_excerpt`, `page`, or `unknown`. | A feed item can identify a story but establish only the supplied excerpt. A page snapshot establishes neither linked-story content nor a complete article corpus. |
| `organization`, `author` | Separate evidenced public publication/organization name and exact item byline. A collective byline may remain as supplied. | “Source: …”, “Author: Unknown” if absent. Do not derive the byline from domain ownership, a publisher About page, author reputation or model output. Page/unknown scope suppresses per-story author. |
| `sourcePublishedAt` | Original story publication date/time with an evidence URL and identified story/excerpt scope. | “Source published”; unknown stays unknown. Do not substitute collection, approval, event start, HTTP Last-Modified, page footer year or an undifferentiated feed update field. |
| `sourceUpdatedAt` | Explicit publisher update date/time for the identified story, independently evidenced. | “Source updated”; an update is not proof of a correction. Preserve the original publication date. |
| `fetched: {url, scope, at}` | Actual successful fetch of the stated asset; scopes `story`, `syndicated_excerpt`, `page`, `metadata`. | “Fetched” plus scope and exact URL. A failed attempt/304 metadata check must not advance the last full-story fetch date. Observation insertion time is not automatically a successful fetch time. |
| `checked: {url, scope, at}` | A separately recorded review/check of the identified asset and stated scope. | “Checked” plus scope and URL. Missing tuples stay unknown. A fetch is not a check; even a story review is not independent verification of every underlying claim. Mismatched story URLs do not establish this story's review. |
| `approvedAt` | Explicit application approval timestamp, including zone. | “Approved by AquidneckAI”; no fallback to any source/fetch/check date. `published_at` is deliberately ignored by this helper; any later adapter must map its semantics explicitly. Approval timestamp does not itself assert currently published status. |
| `evidenceKind` | Reviewed classification: original reporting, first-party statement, commentary, research, directory lead, syndication, unknown. | Attribute institutional/maker claims as claims; directory rank, publication familiarity and research maturity do not imply tested local results. |
| `canonicalClaim`, `syndicationOriginal` | `{url, evidenceUrl}` linking an evidenced canonical declaration or reported original. | Preserve observed URL and attribution. Hints create possible duplicate review, never automatic rewriting, merging or treating a syndicated copy as independent corroboration. |
| `rights.access` | Reviewed asset-level `public`, `snippet_only`, `restricted`, `unavailable`, unknown. | Public readability is not a license. No bypass, subscription, login or full-text fetch is implied. Unknown/unavailable access is visible. |
| `rights.reuse`, `rights.commercialDisclosure` | Evidenced claims describing reuse limits/attribution requirements and disclosed sponsorship/affiliate context. | Unknown does not mean freely reusable or independent. Default reader plan is a link plus independently written, reviewed summary, subject to a separate source-specific rights review. No article/image republication permission is asserted. |
| `condition: {state, evidenceUrl, at}` | Evidenced `corrected`, `outdated`, `withdrawn`, or unknown; `at` is an optional evidenced source date. | Display a visible status and dated evidence when known. A recent fetch/approval cannot establish “current.” Do not infer withdrawal from a temporarily unavailable page or age alone. Correction requires renewed review of affected wording. |
| `localFact` | Public, reviewed factual statement with a source evidence pointer. | “Local fact from source”; e.g. an explicitly stated Newport location. Exact private excerpts stay in editorial evidence, not this object. |
| `editorialInterpretation` | Separate reviewed AquidneckAI explanation of potential usefulness. | “AquidneckAI interpretation”; never promote generic local usefulness or predicted benefit to source evidence. A broader idea can have no local fact and a clearly labeled interpretation. |
| `issues` | Fixed validation codes for incomplete story/check scope or contradictory date order. | Development/review diagnostics, not automatic publication decisions. Absence of an issue is not approval, freshness, complete provenance or factual verification. |

All returned keys, including nested objects, are constructed explicitly. No input-object spreading or private notes, model reasons, assessment output, source IDs, account identifiers, raw text or review history is copied. The public projection tests inject private sentinel fields at every object level and require identical output to clean fixtures. This is structural filtering, not a PII detector: public-safe review of allowed prose and URLs remains necessary. This helper is not a network-request/SSRF validator and never fetches any URL.

## Dates, corrections and link identity

Only validated ISO calendar dates and explicit-offset instants with seconds are accepted. Date-only source values retain their day and precision; never fabricate midnight, a local zone or relative freshness. Fetch/check/approval require an instant. Missing zones, locale dates, impossible dates, leap seconds, `24:00`, unsupported precision and unknown `-00:00` offsets stay unknown rather than undergoing permissive JavaScript parsing. Explicit positive/negative offsets normalize to UTC; DST ambiguity is resolved only by the supplied offset. Rendering can localize valid instants later while preserving date-only days.

Original source date, source update, fetch, check and approval remain separate even when order is inconsistent. Updated-after-check and update-before-publication/approval-before-publication instant comparisons produce review issues without repairing timestamps. Date-only comparisons do not assert intra-day ordering. A 2020 article approved in 2026 still has a 2020 source date. Neither age nor recent fetch alone establishes expiry/current status. A correction notice, expired opportunity or withdrawal retains its source link and provenance; future production status/withdrawal handling remains in the existing editorial lifecycle. The offline helper does not publish, withdraw, rank or hide records.

URL parsing uses the standard URL serializer (including hostname/default-port, encoding and dot-segment normalization). Beyond that it does not remove tracking-looking query keys, reorder queries, drop fragments, lowercase paths, change HTTP to HTTPS, remove `www`, follow redirects, collapse trailing slashes or apply canonical hints. Different parameters may identify different stories; fragments may identify distinct index entries. Same serialized URL means possible revision identity, not duplicate content. Cross-host canonical/syndication links require evidence and human review; matching titles or reused prose are not independent corroboration. Future deduplication must preserve publisher/byline/revision history and links to each observed copy.
